# Availability and installation

Keep `skills/second-brain/` in the suite repository as the canonical skill. Improve
this package rather than installing a second competing brain router. The entry
and its relative references can be fetched at a GitHub branch/ref by a connected
dot; resolve them in that same tree. Fetch current target-repository contracts
separately. The package intentionally contains no personal repository identity.

For a local harness, intended discovery is `~/.agents/skills/second-brain` pointing
directly to the canonical suite directory. Use the suite's existing setup/link
procedure only when installation is needed. Do not retarget an installed skill
to a temporary task clone. Check the resolved path and loaded metadata.

For cloud dot, intended installation is the host's personal skill library with
this `SKILL.md`, references and scripts retained. Use the host's supported
skill-create/import operation if actually exposed. A local symlink, GitHub PR,
Library upload or reading a skill file does not itself install a cloud skill.
If no cloud import tool is callable, return the complete `.skill` ZIP and
GitHub entry URL as ready artifacts and identify cloud installation as pending.
Do not claim automatic model discovery until the parent verifies it.

Verify discovery in the **parent dot environment** after supported installation:

1. Confirm its skills inventory lists `second-brain` with the updated description.
2. Load that exact skill and one relative reference. Confirm no unresolved
   local-only `~/...` path was needed for the dot-runtime branch.
3. Run a read-only capability check on the intended private repository.
4. Ask a synthetic query/capture planning prompt and check that dot selects its
   own runtime, reports actual capabilities and does not perform a test write.

Only then report cloud skill loaded/discoverable. Runtime execution and repository
publication are separate capabilities and still require their own observed tests.
